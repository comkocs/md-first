# md-first
结尾处我会随时更新Readme，包含任何AI技巧。
**一个人指挥一群 AI 窗口干活时用的一套 md 文件，外加一个工单台。**

不是 skill，不是 agent，不是 MCP。底下是同一件事：
**把你的规矩和习惯写成文件，AI 开口之前先读一遍。**
那个文件后缀叫 `.md`，用记事本就能打开改。

来源：一个真实项目。一个人不写代码、只拍板，指挥十几个 AI 工位、
几十个一次性员工窗，十七天产出约三十六万行代码、2900 次提交。
文档里每一条规矩、代码里每一道闸，后面都对应一次具体的事故。

> ### ★ 这个仓是给**新项目**用的
>
> **熟练 AI 的老手请移步 → [md-first-handover](https://github.com/comkocs/md-first-handover)**
>
> 判据很简单：**项目已经在跑，而且已经有一份给 AI 看的记忆文件**
> （`CLAUDE.md`、`AGENTS.md`、`.cursorrules`，或你自己攒的章程、笔记）。
>
> 这里那四份会让 AI 在你项目根再建一套 `宪法.md` / `项目.md` / `DECISIONS.md`。
> 你已经有一份规矩了，再来一份就是**两份真源**：AI 没有优先级可依，
> 会自己挑一份、或者把两份揉在一起，**而且不报错**。
>
> 那边的做法相反——不往你的老项目里塞东西，而是让老窗口导出一份交接件，
> 由一扇新窗口读。你的项目一个文件都不动。

## 快速开始

### 最快：把这一句发给你的 AI

**不用自己下载，不用装任何东西。** 打开任意 AI 的桌面版 / 命令行
（能读网页、能在你机器上写文件的那种），把下面整段发给它：

```
打开 https://github.com/comkocs/md-first ，把整个仓下载到本地。
读 README.md 里的选档表，按它的判据告诉我该用哪一份（一句话说清判断和理由），
然后只读那一份，照它说的跟我协作。判错了我会说。
★别把文件复述给我听，直接开始。
```

已经知道自己要哪一档的话，直接点名那一份，更省事：

```
打开 https://github.com/comkocs/md-first 下载到本地，读 1-小型.md，
照它说的跟我协作。别复述给我听，直接开始。
```

> **前提**：这条路要 AI **能访问网页、能在你机器上写文件**
> （桌面版、IDE 插件、命令行工具都行）。只能聊天的网页版办不到——
> 那就走下面的手动三步。

### 或者自己来（三步，五分钟）

#### 1 · 挑一份

**只挑一份。** 四份对应四种规模，不是四个章节。

| 文件 | 适用 | 它防的失败 |
|---|---|---|
| [**0-新手.md**](0-新手.md) | 还没想清楚要做什么；或者看到一个网站 / App 想做个类似的 | 你说「做一个和 XXX 一样的」，AI 照做了 |
| [**1-小型.md**](1-小型.md) | 模块 5 块以内，第一版做 1 块，开着 2 扇窗 | 换窗失忆 |
| [**2-中型.md**](2-中型.md) | 模块 6～15 块，同时开着 3～6 扇窗；你还亲自派活，但记不住谁在做什么 | 自述当真 |
| [**3-大型.md**](3-大型.md) | 模块 15 块以上，7 扇窗以上；你已经不直接跟干活的说话了 | 并发撞车 |

**选档判据只看三个可数的东西**：模块清单几块、第一版做几块、现在同时有几扇窗在干活。
前两项是计划，第三项是现状——**三项对不上时以现状为准**。

一句话自检：

- 还记得住现在有哪几件事在办 → **小型**
- 记不住了，但还是你一个个亲自派活 → **中型**
- 已经在跟「管事的」说话、不是跟「干活的」说话 → **大型**

代码量只作参考，不作判据（开工前估代码量几乎总是估错）：
小型几百到几千行、中型一万上下、大型十万以上。

判据里**没有「几天 / 几周 / 几个月」**：项目要做多久，跟该用哪一档无关——
一个要做三个月的项目，第一天照样只有两扇窗。

选哪一档由你决定。拿不准就往小了选：升档是加东西，降档要把已经长进流程里的表格拔掉。

#### 2 · 放进你的项目

把挑中的那一份复制进项目目录。**可以改名**，例如 `我的规矩.md`、`AI须知.md`。

> **避开这四个名字**：`宪法.md`、`项目.md`、`进度.md`、`DECISIONS.md`。
> 它们是文件里让 AI 建的，重名会被覆盖。

不合用的条目直接删。这些是给 AI 读的纸条，不是代码。

#### 3 · 开窗，贴这一句

```
读 <你刚才那份文件的完整路径>，照它说的跟我协作。别复述给我听，直接开始。
```

**AI 读不到你硬盘上的文件**（办公沙箱类、只能聊天的网页版都属于这种）？
那就**把那份 md 当附件上传**，然后说：

```
照这份文件说的跟我协作。别复述给我听，直接开始。
```

剩下的它会问你。（沙箱类还有一处不同：它写不进你的盘，让它建的文件得你自己保存。
详见文末常见问题里「我用的是办公类 AI」那条。）

## 用办公类 AI 的看这里（沙箱环境）

指 WorkBuddy、豆包工作台这类**跑在沙箱里**的 AI：能聊天、能读你上传的附件，
但**读不到你电脑上的文件、也写不进去、更不能跑命令**。

### 能用一半，这条线很清楚

| 文件 | 在沙箱 AI 里 | 为什么 |
|---|---|---|
| [**0-新手.md**](0-新手.md) | ✅ **完整适用** | 零工具依赖。就是问你三个问题、把需求拆开、产出一份 `项目.md` |
| [**1-小型.md**](1-小型.md) | ✅ **适用** | 三件套全是 md，没有必须敲的命令 |
| [**2-中型.md**](2-中型.md) | ❌ **不适用** | 它的必做动作里包含装工单台 |
| [**3-大型.md**](3-大型.md) | ❌ **不适用** | 要工单台的服务端 |
| `ticket-desk/` | ❌ **不适用** | 要 Python 3.10+ 和命令行。**这条没有变通办法** |

**别因为这个就去够 2-中型。** 绝大多数办公场景本来就该待在 0 或 1
（模块 5 块以内、同时开着 2 扇窗）——那正好是完整适用的两档。

### 三步怎么做

**第一步 · 拿文件。** 不用 git、不用下载工具：

- 直接在这个页面上点开 [`0-新手.md`](0-新手.md) 或 [`1-小型.md`](1-小型.md) 就能读，GitHub 会自动排版
- 要存下来：点进那份文件 → 右上角 **Raw** → 右键另存为
- 或者仓库首页 **Code → Download ZIP**，解压出来跟 txt 一样

**第二步 · 交给 AI。** 别给路径（它读不到），**把那份 md 当附件上传**，然后说：

```
照这份文件说的跟我协作。别复述给我听，直接开始。
```

**第三步 · 它产出的文件，你自己存。**
文件里让它建的 `项目.md`、`宪法.md`、`DECISIONS.md`，
沙箱 AI 写不进你的盘，只能把内容打出来——**你新建文本文件粘贴保存**。
下次开新窗，把这几份连同那份 md 一起上传。

### ★这一步偷懒，整套就没了

上面第三步是这套东西在沙箱里的**唯一命门**。

这套方法靠「文件」换窗不失忆，而在沙箱里，**那个文件系统就是你自己**。
你哪天嫌麻烦不保存、不回传，它就**静默退化成一场普通聊天**——
不报错，你还以为规矩在跑。这正是本文反复讲的那种失败形状：
**一路顺畅地把错事做完，中间什么都没提示。**

> 说白了：沙箱 AI 缺的是**手**，不是脑子。方法一个字都不用改，搬运由你来做。
> 每天多花两分钟上传和保存，换的还是同一件事——
> **下一扇窗读文件，不读聊天记录。**

## 它解决四件事

| | 症状 |
|---|---|
| **换窗失忆** | 换一扇窗就要重新交代同一件事，昨天说好的今天再说一遍 |
| **自述当真** | AI 说「做完了」，其实没有，而你信了 |
| **并发撞车** | 两扇窗改坏同一个文件，而且没有任何报错 |
| **真源漂移** | 同一个事实写在两个地方，过几天就漂开，也不会报错 |

这四件事都还没遇到过的话，这套东西暂时用不上。

## 核心设计

### 至少两扇窗

```
策划窗  ← 你跟它说话。听需求、拍板、记账、验收。不写实现。
工位窗  ← 干活。只看见一张纸条，做完就交。不在这里提新需求。
```

沟通和干活抢同一份上下文，而**先满的是沟通那边**——满了之后它开始丢最前面那段，
而那一段正是最早提的需求，且**不会有任何提示**。

四份里都写着这一条。它与「写代码」无关：写文章、剪视频、做 PPT 同样适用——
一扇聊选题定结构，另一扇拿着定稿去写去剪。

### 要开新窗，必须是「一句话 + 一个 md」

```
读 <完整绝对路径>，照做。先做「<哪一件>」那一条。
```

路径从盘符写全（相对路径在新窗里没有意义），md 要先存在，那句话要能一键复制。
**新窗读不到当前这段对话——文件能被下一扇窗读到，对话不能。**

### 四条底线（四档通用）

1. **自述不算数。** 「我做完了」和「我验证过了」是两句话，后者要给出命令与原样输出。
2. **一个事实只存一处。** 要抄之前先问：那份抄件过期了，谁会发现？
3. **写下来的东西要能回指。** 每条结论都说得出是从哪来的。
4. **规矩只拦「活没做好」。** 拦「字没写对」的规矩降级成记一行、继续做——
   否则它会被绕过，而被绕过的规矩比没有规矩更坏。

## 为什么低配模型用这套也不容易跑偏

拿最便宜、最容易跑偏的那一档模型（某家的 flash 档）实测过一整轮：
装工单台、建第一张单、跑开窗指令、扫残留问题、写分诊清单。整轮没有跑偏。

它自己给的解释：

> 「一个 flash 看起来像 opus，通常说明出题和脚手架好；反过来出题弱的时候，opus 也得靠猜。」
>
> 「这套东西把**判断**换成了**检查**，跑偏的模型没有可发挥的空间。」

"模型弱"通常不是指推理弱，而是下面这三样弱——**而这三样都能从外部补上**：

| 弱在哪 | 症状 | 这套文件怎么补 |
|---|---|---|
| **边界感** | 让它加个登录，它顺手重构了整个目录，理由还挺像样 | 写死「不能碰什么」，并写出**为什么**。只写"不许改 X"，它遇到非改不可时只能停车问人；写了原因，它能自己判断 |
| **规则感** | 说"做完了"，但那是它自己认定的做完 | 把「做完」变成一句能验的话：点哪里 / 跑哪条命令 / 看见什么 |
| **记性** | 聊到第三十轮开始丢掉最早的需求，且不会提示 | 结论写进文件，下一扇窗读文件、不读聊天记录 |

具体落地的几条设计，都**不依赖模型聪明**：

- **选档靠读数，不靠判断**——模块几块 / 第一版几块 / 现在几扇窗，填一个固定模板得出建议。
- **让它做判断题，不做问答题**——拆解需求时每一块后面都要填「我猜你要 / 不要」。
- **一次给完，不走五轮对话**——省的不只是你的时间，是它的上下文。
- **报错必须给出路**——只说"不行"的闸，低配模型会卡在那里。
- **不许复述文件**——那几百字纯消耗，而且你已经读过。

这三样都不是换更贵的模型能根治的：**更大的上下文只是把问题推后，不是解决它。**

★**这个仓本身就是这条论点的样本**：它的文档与代码都是 AI 在上面这些规矩下写出来的，
人只出想法、拍板、验收。提交历史里能看到全过程——
包括几次「测试在推荐配置下跑不起来」「文档照抄起不来」这类由检查发现、
而不是由人眼发现的问题。

## 四十条教训

如果只看一个文件，看 [3-大型.md 第四节](3-大型.md#四四十条最疼的教训)。
每条一句话，后面对应一次真事故；小项目也适用。开头三条：

> **1.** 自述全绿不等于跑过。谁执行谁不检。
>
> **2.** 钉「代码长什么样」的用例，拦不住「代码干了什么」——
> 一小时内连着把生产改坏两次，两次用例都是全绿的。
>
> **3.** 变异检验活下来的时候，那才是要查的时刻——它说明这条路今天根本没被测到。

### [`ticket-desk/`](ticket-desk/) —— 工单台

窗口多到管不过来那天要装的东西。**不是记事本，是一套带闸的台账。**
Python 3.10+，标准库实现（只有图片功能需要 Pillow），38 条命令 + 一个网页台面，
521 条测试。单机模式零配置可跑，也支持服务端多机协作。

```bash
cd ticket-desk
python -m pytest tests -q          # 521 passed
python ticket_desk/ticket.py serve --open
```

#### 它到底管什么

这些名词现在满天飞，所以按**它替你解决的问题**来说，不按名词来说：

| 你遇到的问题 | 它怎么管 |
|---|---|
| **换窗就失忆** | 一条 `receipt` 把任务书、上一轮为什么被退、当前值面一起带进新窗；`export` 能把一张单打成离线包 |
| **AI 之间没法传话** | 三条通道 + 每张单一条对话线（`say` / `ask` / `answer` / `inbox`），窗与窗之间靠文件和台账交接，不靠你转述 |
| **同一个事实到处抄** | 「当前值面」(`state`)：判据图尺寸、部署头、延迟预算这类共享事实**只存一处**，各窗读它、不抄它 |
| **说做完了其实没有** | 四道闸：建单要写清实机消费者与交付项，交板要给验证命令与原样输出，判卷要写「怎么打开它」，并线要「判过 ∧ 复验过」 |
| **不知道哪个模型靠谱** | 两本账分开记：**模型记分**与**出题记分**。判退时必须标责任方，于是弱任务书不会拖垮强模型的合格率 |
| **长期工位记不住自己的事** | 固定工位有自己的 `memory`（一份工位记忆 md），换窗自动带上 |
| **页面越刷越慢** | 增量刷新用**流水行号**当书签，不用时间戳（时间戳会撞「同一秒两笔写入」） |
| **忘了谁在等什么** | `digest` 一眼扫完：新单、停滞、阻塞、待复验、可并、各模型合格率 |

还有：SQLite 存储与文件目录双形态、HTTPS + 令牌鉴权、服务端全文搜索、
协议版本握手与安全降级、上服包打包与部署记录。

> **它不是 skill、不是 MCP、不是 RAG，也不想是。**
> 那几样解决的是「**让模型知道更多**」；这个解决的是
> 「**让一群窗口在同一套规矩下把活做完，并且做没做完能查**」。
> 它不往模型里塞上下文，它管的是上下文之外的那部分——谁在做、做到哪、凭什么算做完。

#### ★能全自动，但别全自动

技术上做得到：你只跟策划位（或总编排）说话，剩下的派单、开窗、交板、判卷、并线
可以串成巡查式的自动闭环。

**但我不推荐。** 这套东西里每一道闸最后都指向同一件事——**谁在拍板**。
全自动等于把拍板也交出去，而 AI 需要人纠偏：它最擅长的失败形态是
**一路顺畅地把错事做完**，中间不报任何错。自动化会让这种失败跑得更快、更远。

留一个人在环里，成本是每天几分钟；不留的代价，是某天你发现三周的活方向就错了。

完整功能、每一道闸的理由、网页台面的用法见 [ticket-desk/README.md](ticket-desk/README.md)（479 行）。

## 常见问题

**我不会 git，不会装 Python，能用吗？**
能，而且**根本不用下载**——这四份就是普通文本，
在这个页面上点开文件名就能直接读（`.md` GitHub 会自动排版）。

要存到自己机器上，三种都行，都不需要 git：

- 点开那份文件 → 右上角 **Raw** → 右键另存为

- 或者把这一句发给**能执行命令**的 AI（桌面版 / 命令行 / IDE 插件），让它代劳：

```
打开 https://github.com/comkocs/md-first ，把整个仓下载到本地。
```

**我用的是办公类 AI（沙箱里的那种），能用吗？**

见上面[用办公类 AI 的看这里](#用办公类-ai-的看这里沙箱环境)。

**需要先学什么？**
不需要。前提只有两个：会说人话、会复制粘贴。

**md 是什么格式？打不开。**
就是 txt，只是后缀不同。右键 → 打开方式 → 记事本。
写得不规整、用大白话、有错别字都不影响，AI 都读得懂，改完当天生效。

**四份能不能一起给 AI 读？**
不建议。四份合计约五万字，单份一万出头。
多出来的四万字不会让它更懂你的项目，只会让它更早开始丢上下文。

**改了 `ticket_desk/config.json` 之后跑测试会红吗？**
不会。测试一律跑内置默认配置，既不读你的 `config.json`，也不读环境变量里那份。

## 结尾的经验总结：
1，任何情况下，复杂工程编码，不能让任何模型产生自动行为，所有跟你吹嘘复杂编码工程可以自动的，都是骗你钱的，以前和人沟通，讲究的是如何让人执行你的决策，而AI是相反的，他们特别遵守规则，遵守到你根本察觉不到他们进入了死循环。

2，任何时候不要被AI忽悠带偏离，他们会莫名其妙钻进一个死胡同，做为“设计者（你自己）”唯一存在的目的就是对AI进行纠偏，他们的记忆是有限的，和人类一样，而唯一不会改变的就是设定好的组织架构，这就是闸口。

3，一个好的组织架构中你就是老板，中枢大脑，而你的TOP级员工才是和你沟通的桥梁，一个大型项目中你无需和普通管理层AI沟通，你需要的是将一个总工/总编/策划/这类员工的记忆提取，分出无数个不同的内容沟通岗位，这种方式适用于所有项目。

4，使用AI时要有一个调教的过程，你需要不断在项目中和你的TOP级AI进行不停的沟通，当文本量达到300K时，你就可以导出它的记忆，且要求它导出和你的工作习惯，这就是初步的工作经验，将使你以后和AI更加沟通简单。

5，唯一能够挡住AI飘移的方式是尽量和它少说话，那么这就违背了内容沟通的定律，不说话就无法核对需求，这时候就必须分窗口，由一个总编级岗位带领项目，而导出总编岗位的记忆分出一个策划或者内容岗位，而当策划岗位飘移时只需要再次导出策划记忆再去拆分自己的项目，可以设置策划1，策划2，策划3以此类推。

6，当你和AI工作后，AI将成为这个世界上最了解你的人，同时你某项技能的上限就决定了AI的上限。当你遇到自己不懂的事情时不要自己胡乱决策，你应该跟AI说“你是专业的，这个我不懂，你决定”，如果某项技能是你专业的，你应该及时主张自己的观念，你的主张AI只会接受，不会拒绝。

7，不要相信什么agent,skill这些词汇，也不要相信多模型协同，真正的多模型协同只存在于每一个窗口做一个指定的任务，这就叫多模型协同，例如本项目的工单系统。最近遇到很多朋友都被网上忽悠瘸了，他们喜欢使用3个模型阅读同一个上下文，这是大错特错的。

8，每个项目都应该要第一时间创建自己的宪法文件，这是AI共同遵守的，宪法会不断迭代更新，规则立好了大楼才不会倒塌。所有宪法都是由AI和设计者（你）之间沟通产生的，没有任何一条是需要你亲自打开宪法文件去写的，你只需要告诉AI你想要什么就可以。

9，再次提示永远不要在一个窗口内又沟通又执行项目，每个模型厂商都有缓存命中率，文字沟通的命中率最高，执行命中率次之，最低的就是又沟通又执行，所以沟通窗口和执行窗口必须分开，哪怕你是最小的项目，这不仅仅是耗费TOKEN的事情，更是让AI幻觉产生更快的事情，只有让AI专注于某一个模块，它才是最聪明的时候。

10，将AI当成人类沟通，但它和人类是相反的，人类会拒绝，AI不会，所以你需要有AI的行为思维模式，你需要不断从他们的顺从中找到他们不合理的地方。。这就和人类沟通一样，你需要在和人类沟通时对方不停拒绝中找到人类的弱点让对方同意你的需求，反过来AI也是如此，这就叫AI思维。
