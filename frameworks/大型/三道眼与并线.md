# 三道眼与并线

## 三道眼分别看什么

```
自检（员工）  跑任务书写死的验证命令，出图，交板
判卷（总监）  方向与质量。开图目检。写「用户怎么打开它」
复验（复检）  事实。在不在主场景、测试绿不绿、真源对不对、硬闸过没过
              自己登录取图、自己重跑、★不读判语
```

**三道并行，不串行。** 员工一交板，复检就能动手，不必等总监判卷；
judge 与 verify 谁先到都行，两道齐了才能并。

串行的代价很具体：一张单的两个人被绑成一条线，复检干等总监，
而总监可能正在别的窗里。

**复检不读判语**是这一节唯一的硬要求。读了判语再验，
你得到的是「对第一次判断的确认」，不是独立的第二次判断。

## 判卷的硬闸

1. 判语必须写清 **「用户怎么打开它」或「设计者怎么打开它」**。
   写不出这句话，多半是这活根本没接进任何人看得见的地方。
   （用户打不开的活——取证、报告、内部工具——写后一句。）
2. 判卷人不能是执行员工本人。
3. 判退必须标责任方（模型 / 出题），且**判语首行与之一致**。
4. 低档模型首检从严，逐行核。

### 判卷人要自己开图

- 判据图必须**自己打开看**，不能只看缩略图。小图判侧脸一定要放大。
- 上级裁定里的**事实前提**也要自己核一次——那个前提也是某个人报的数。
- **判据图只从登记的根目录开**：从别处拿的同名图可能是上一轮的。

### 判卷要问「用户实际走哪种路」

场景覆盖也是判据。只走正交直线的验证漏掉过斜向移动的真因，连漏两单。
判之前问一句：真实使用者会怎么走？那条路验了吗？

## 并线条件

```
判过 ∧ 复验过
```

内部单交板时带机器闸报告，各项全绿 ⇒ 自动记复验过，复检并线时只看闸输出。
**缺一项或任一项不过 ⇒ 不置标**，照旧要人工复验。

★宽松解析在这里等于把闸拆了：台面会显示「机器闸绿」，谁都不会再去看那张单。

## 并线铁律

**1. 零 git 冲突 ≠ 能并。**
合并树必须真跑一次构建 + 全部测试工程。语义冲突在 git 那里完全沉默——
一轮撞过五次语义车，其中两次 git 一个字都没说。
定责只靠隔离对照：把两支各自单独合一次，看哪一支自己就红。

**2. 两窗不许把同一个递增号抬到同值。**
协议号、迁移号、快照版式号。同波多单的号由总监按族**预分**并写进任务书。
撞了的话 git 只在那一行冲突，随手一解就过，盘上写出「半截 v7」，下一次开机崩。

**3. 主检出只用快进合并，永不 `reset --hard`。**
主检出是共用的。跑之前先 `git status` 看一眼别位有没有未提交的东西——
实犯过，清掉过别人正在写的文档。

**4. 未判的提交不随支头进主线。**
按当前支头并，但先核祖先关系：别位报的支头多半已经过期（一天撞过四次）。

**5. 台面记「已合并」以远端看到新头为准。**
本地看得见 ≠ 已发布。

**6. 判过 ≠ 能并。不让主线红着过夜。**
退回时要给：隔离归因 + 逐条期望值 + 归属 + 「改测试还是改真源」。
少任何一条，那张单会在退回与重交之间来回三轮。

**7. 合并放行只认独立复检。**
判语里写「可整批并」不算数——那是判卷人对拓扑的猜测，不是拓扑本身。

## 上服

- 主线动了 ≤2 小时脚本自动上服。
- **取证与上服分离**：上服成没成看探针，取不到图不挡上服。
  绑在一起的时候，一批部署单卡在「待取证」上，而线上其实早就跑起来了。
- 部署脚本的 READY 行是**纸糊的闸**：日志是追加的，上一次的旧 READY 照样被 grep 到。
  真判据只有一个——端口现在在不在听。
- 上服记录是「已经发生的事实」，免员工窗、免判、免复检。取证另开一单。
