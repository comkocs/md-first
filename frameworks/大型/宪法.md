# 大型项目宪法

> 适用：一个人 + 十几个固定位 + 员工池，数月。
> 这一档解决的是**「谁在做什么说不清」**。它比中型档贵得多：
> 你每天要花 1–2 小时在编排上。上这一档之前，先确认你真的到了那个规模。

## 一章 层级

```
设计者（唯一拍板人；不写代码，只拍板）
  └ 总编排（公共接口：协议号、登记表、合并授权、裁定落笔）
      └ 总监位 × N（每位管一个模块，从素材到进产品一口气负责）
          └ 员工（一次性窗口，只做工单上的活；不 commit 不 push，除非工单写明）

复检·合并与部署：独立于指挥链，谁也不指挥它。
平台位：工单系统本身的开发运维，不碰业务。
策划/分发位：设计者在某一类事务上的唯一对接人，只转述不实现。
```

**「一口气负责」是这一档的核心。** 一个模块从需求到上线由**同一位**负责，
不按前端/后端切。按工序切的后果是固定的：接线那道工序无人认领，
每个人都做完了自己那段，而东西没接上——**而且没有人觉得是自己的责任**。

## 二章 通道：一切走工单，聊天不留痕

1. 口头说过的事**不算数**。要它发生，就得有一张单。
2. 改已派任务书口径的裁定，必须以需求单发到受影响位；**写在自己线上不算送达**。
3. 一次开窗只走一张单。派出之后不在原地改口径——要改就判退返工，或作废另建。

### 建单必填闸

| 必填 | 为什么 |
|---|---|
| 实机消费者 | 这个产物被谁加载？填不出=活还没想清楚，不发车 |
| 交付项（逐行路径） | 叙述句永远交不了板，交板时逐条当路径核 |
| 任务书路径 | 开窗指令要贴它；建单前写 `{ticket}`，服务端分配到号后替换 |
| 任务档 | 甲/乙/丙。丙档另必填上下文预算且 ≤2000 行 |
| 可感知/内部 二选一 | 漏标不是「默认内部」，是拒绝建单 |

★**先建单，再把单号写进任务书**。反过来（先猜号写书、再建单）一定会写错号。

### 答复闸

需求单的答复首词只认三种，别的一律拒：

```
受理（后面可跟预计）
已排期→T-xxxxxx（派单号）
已完成→T-xxxxxx（交板单号）
```

一句「好的」也能把单从待答列表里抹掉，而排期与交板单号**一个字都没留下**。

## 三章 三道眼

```
自检（员工）：跑任务书写死的验证命令，出图，交板
判卷（总监）：方向与质量，开图目检，写「用户怎么打开它」
复验（复检）：事实——在不在主场景、测试绿不绿、真源对不对、硬闸过没过
             自己登录取图、自己重跑、不读判语
```

**三道并行，不串行。** 员工一交板，复检就能动手，不必等总监判卷。
并线条件 = 判过 ∧ 复验过。内部单机器闸全绿视为复验过。

判卷硬闸：判语必须写清「用户怎么打开它」或「设计者怎么打开它」，写不出不能判过。
判退必须标责任方（模型 / 出题），且判语首行与之一致。

## 四章 并线铁律

1. **零 git 冲突 ≠ 能并。** 合并树必须真跑一次构建 + 全部测试工程。
   语义冲突在 git 那里是完全沉默的。
2. **两窗不许把同一个递增号抬到同值**（协议号、迁移号、版式号）。
   同波多单的号由总监按族**预分**，写进任务书。
   撞了的话 git 只在那一行冲突，随手一解就过，然后线上开机就崩。
3. **主检出只用快进合并，永不 `reset --hard`。** 主检出是共用的；
   跑之前先 `git status` 看一眼别位有没有未提交的东西。
4. 台面记「已合并」以**远端看到新头**为准，不以本地看到为准。
5. **判过 ≠ 能并。** 不让主线红着过夜。

## 五章 上服

- 主线动了 ≤2 小时脚本自动上服。
- **取证与上服分离**：上服成没成看探针，取不到图不挡上服。
- 上服记录是「已经发生的事实」，免员工窗、免判、免复检；取证另开一张单。

## 六章 记忆

- 每个窗口只装自己那一层：员工装工单，总监装章程 + 本位工单，总编排装宪法 + 日览。
- 长文档只准**顶部追加**（裁定 DECISIONS、笔记 NOTES），每月归档。
- 上下文用到八成：提交、在工单记一行断点、收窗。换窗只带「现状与下一步」。
- 固定工位的记忆由工具从**已交板的单**自动生成；自述只占一小节，且标明是哪个模型写的。

## 七章 边界

- 任何总监**不改协议、不改核心数值、不动别位目录**。
- 例外：一条龙单（一个工位包干一个功能模块从后端到前端）内准跨位改，
  回执列「跨位改动面」，归属位事后对齐**不反改**。
- 位内判据要生效，必须写进本章程；写在接管件里的判据不算数。

## 八章 闸的纪律

1. **闸只拦「活没做好」。** 真业务闸（真源缺、接口对不上、判据不达、测试红）才允许停车。
2. **非业务闸不停车**：路径写法、后缀、账面状态、工具版本——记一行，继续做。
3. **闸不许挂在会移动的东西上。** 「与当前主线一致」「相对某个老基点的 diff」
   这类判据在定义上就不可能稳定满足。判据要能自证；新鲜度另走，只报不拦。
4. **卡住员工的工具账立刻修根**，不要让员工替工具的毛病买单。
5. **钉哈希/钉源码文本的闸要对真源当前头。** 绿着钉错基准，比没有闸更坏。

## 九章 拍板人（设计者）

- 只有他能拍板。总监拿不准时**直接在窗内问他**，不经总监层层传递。
- 他记得逻辑，**不记得数值**。要他定数时把既有常量摆出来让他选，不要问开放式的「多少」。
- 给他讲数值用白话。术语一出他会说「没听懂」，然后随便填一个。
- 他后说的**压过仓里的旧真源**；旧真源是「待更正」，不是依据。
- 他说「以后可能改」= 现在就要做成一个具名常量 + 单一入口。

## 十章 本宪法自身

- 改宪法要落号（DECISIONS 顶部追加），并以需求单广播到受影响位。
- **裁定可能在落号前就被推翻**：落号前问一句「这条还成立吗」。
- 总监的判语是快照，不是永久事实。
