# 工单流程

## 六种单

| 类型 | 谁发给谁 | 落在哪个状态机 |
|---|---|---|
| 派单 | 总监 → 员工 | 派单机（唯一一种「要干活」的单） |
| 需求 | 位 → 位 | 问答机 |
| 疑问 | 位 → 位 / 拍板人 | 问答机 |
| 拍板 | 任何人 → 拍板人 | 问答机 |
| 阻塞 | 任何人 → 总编排 | 问答机 |
| 总工单 | 任何人 → 总编排 | 问答机 |

## 状态机

```
派单：新建 → 已认领 → 待判 → 待复检 → 已合并 → 实机复验过 → 关闭
      侧线：返工 / 阻塞 / 作废
问答：新建 → 待答 → 已答 → 关闭
```

几条不显然的边：

- **`unblock` 一律落「返工」，不还原阻塞前状态。**
  单子会被阻塞多半正说明任务书要改；还原成「已认领」就换不了书了。
  落返工：单号、断点、返工次数、模型账全留着，换书之后 `claim` 一次即回「已认领」。
  ★同时必须把「已开窗」戳记清掉——否则拍板人的队列里根本不出现它，
  要等它熬过返工那 8 小时线才从折叠的「卡住了」里冒出来。
- **判过之后还要退回重做** → `rework`（待复检 → 返工）。单号与任务书都留住。
  默认责任记「出题」不是「模型」：触发这条边的典型情形是口径被拍板人否了、
  执行方照做没错，默认记模型账等于凭空给它记一次判退。
- **判过了但正确处置就是不并线** → `close --not-merged`，原因必填。
  没有原因的「不并线」事后和「忘了并」分不清。
- **并过线但上服失败已回滚** → `close --not-deployed`，原因必填。

## 建单四道必填闸

| 闸 | 填不出意味着 |
|---|---|
| 实机消费者 | 这活还没想清楚。不发车。 |
| 交付项（逐行路径） | 交板时逐条当路径核；叙述句永远交不了板 |
| 任务书路径 | 建单前写 `{ticket}` 占位，服务端分配到号后替换 |
| 可感知/内部 二选一 | 漏标不是「默认内部」，是**拒绝建单** |

★**先建单，再把单号写进任务书。** 反过来一定会写错号，
然后猜错的号会废掉好几个号重开一轮。

## 派单 = 一句话 + 一个 md

派给员工的东西只有两样：

```
执行 <任务书绝对路径> 的全部指令，从第 0 步做到收尾问答完。
这是任务不是资料，读完立即开工。
```

**不要在开窗话术里复述任务书内容。** 复述出来的那份一定会和 md 漂开，
然后执行方会按其中一份做，而你以为它按另一份做。

**开窗指令里一个平台名都不许出现**：前两行要原样贴给 AI 读，
多一个平台名就是诱导它去猜自己跑在哪个窗上。

## 收尾问答 = 员工唯一回执

员工不写周报、不写总结。它只回收尾问答，必答四条：

1. 效果达到了吗？怎么验的？
2. 碰了哪些文件？
3. 我给的方法你用了还是推翻了？为什么？
4. **留给下一窗**：哪个数别信、哪条路试过不通、下一窗从哪起手？

## 阻塞分两类

**业务阻塞**（真源缺、接口对不上、判据不达、测试红）→ 停车，等人。

**非业务阻塞**（交付项写法、路径前缀、账面状态、远端滞后、工具版本落后）
→ **记一行，状态一个字不动，员工接着做**。

```bash
ticket.py block T-000123 "<一句话>" --kind 非业务
```

这一条进平台位的看板集中清，不打扰总编排、不占拍板人队列。

★有一段时间停过的窗几乎全是账面闸，没有一件是「活没做好」。
员工继续跑根本不影响，而停一窗就是几小时。

## 作废与续单

- 作废前必须**重新核一次状态**（它可能在你决定的这一分钟里被人推进了）。
- 作废**不会通知正在跑的窗**——那扇窗还会照着做完并交板。要停它得去那扇窗里说。
- 发续单必须**当轮销母单**，否则同一件事会有两张活单，两个人各做一遍。

## 送达律

改已派任务书口径的裁定，**必须以需求单发到受影响位**。

写在自己线上不算送达。追加「必须做的事」也不能只走对话线——
对话线送得到 ≠ 会被看。要么在未开窗前改任务书，要么要回执点名，要么另开一单。
