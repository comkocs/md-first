# 组织与工位

## 怎么切位

**按模块切，不按工序切。** 一个位从需求到上线一口气负责一块东西。

按工序切（前端位 / 后端位 / 测试位）的失败形状是固定的：
每个人都做完了自己那段，而东西没接上——**接线那道工序无人认领**，
而且没有人觉得是自己的责任。这是这套东西里代价最大的一个根缺陷。

一个可以照抄的起点（十个位）：

```
前端·界面与交互      前端·视觉与资源
后端·服务与接口      后端·数据与规则
内容·文案与真源      测试·质量与用例
设计·裁定分发        复检·合并与部署
平台·工单系统        总编排
```

位数上限大约是十三四个。再多，编排位一天扫不完自己的收件箱，
而扫不完的收件箱等于没有收件箱。

## 三个特殊角色

### 总编排

公共接口，不是上级。它管四件事，**只管这四件**：

1. 递增号的分配（协议号、迁移号、版式号——两窗抬到同值就是上服即崩）
2. 各类登记表（谁占了哪个号、哪个模块归谁）
3. 合并授权
4. 裁定落笔（把拍板人的话落成带编号的决定）

它**不判卷**（那是各位总监的事），**不并线**（那是复检的事）。
总编排一旦开始判业务活，它会变成瓶颈，然后所有人等它。

### 复检·合并与部署

**独立于指挥链，谁也不指挥它。** 这是它唯一的价值来源。

- 不采信自述：自己登录取图、自己重跑测试、**不读判语**。
- 排并线次序、推远端、部署。
- 它自己的单（部署单、复检工具单）三方互斥闸在数学上无解——
  那种情形放行自记，但落库标「自记·待终验」，**不伪装成第三方**。

### 策划 / 裁定分发位

拍板人在某一类事务（通常是数值、物品、规则）上的**唯一对接人**。

它只做一段：逐字记录裁定 → 送总编排落号 → 按影响面用需求/疑问单广播。
**不派实现单、不判卷、不并线**——让传话的人给活打分，是这条的反面。

设这一位的理由：拍板人会在任意一扇窗里随口定一件事，
没有对接人的话，那句话就只活在那扇窗的上下文里，窗一关就没了。

## 员工

- **命名 = 「位名-编号」**，编号不复用，到终态自动退役。
  不复用是有代价的（号一直涨），但同一个 `-37` 在两个时期指向两个人时，
  查判退责任会错到别人头上——那个代价更大。
- 员工**不 commit 不 push**，除非工单写明。
- **固定工位**（跨单保留记忆）每位最多三个。记忆写在接管文档里，不在窗里。

## 模型档位与名册闸

| 档 | 意思 | 任务书 |
|---|---|---|
| 甲 | 主力，能自由发挥 | 只写效果/红线/验收，方法不写死 |
| 乙 | 中档，按步骤 | 写清步骤与验收，允许小范围自选 |
| 丙 | 低档 | 模板化，步骤逐条，上下文 ≤2000 行 |

**名册闸：低档模型只能吃丙档单。**

两条配套纪律：

1. **主力模型绝不停用。** 到停用线只通知，停不停是人的动作，要留原因。
   自动停用误伤过两次主力，一停就是所有位停摆。
2. **换模型是小事，不广播、不落号。** 弱位少说话；大张旗鼓地宣布换模型
   会让各位开始揣测「是不是我做得不好」。

## 判退责任要分两本账

- `模型` —— 执行方做错了。计入模型合格率。
- `出题` —— 任务书或判据本身写错了，执行方照做没错。**不计模型账**，
  记进该总监的出题账。

不分开记的话，弱任务书会把强模型的合格率拖垮，
然后有人据此把那个模型换掉——而真正该改的是出题的人。
