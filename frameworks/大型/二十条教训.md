# 最疼的那些教训

每一条后面都有一次真事故。按「在哪一步会咬你」排，不按重要性排。

> 标题不写条数：这份会随着新撞到的事故往后加，
> 写死一个数字的结果是每加一条都要回来改标题，然后总有一次忘了改。
> （文件名里那个「二十条」是早先留下的，改它会断掉两处链接，不值当。）

---

## 做事的时候

**1. 自述全绿不等于跑过。谁执行谁不检。**
执行方复述自己刚才的推理，不是重新验一遍。要另一双眼睛。

**2. 真错别被 `2>/dev/null` 吞掉。**
「这是预期内」的文案必须同时写下**失效条件**——否则它会在真的出事那天继续安慰你。

**3. 把东西放进某处，做完必须读回来比一次。**
最坏的一次：自己写的打包脚本用了一个不存在的 git 选项，错误被吞掉，
脚本照样打印「已写入」——包里其实什么都没有。

**4. 本机时区先核，再报别人时钟坏。**
「服务器时间快了 8 小时」有九成概率是你自己时区没核。

**5. 数好得离谱先怀疑量法。**
没有任何改动能解释的提升，判过也要写死「量法可能不同源」。

**6. 报数别拿单次采样吹倍数。先量后改。**
报障是症状不是归因——「刷新慢」的病根可能在传输不在计算。
接手现成方案先量收益能否兑现：照抄只降 10.7%，换个方案降 63.3%。

---

## 并线的时候

**7. 零冲突 ≠ 能并。合并树必跑构建 + 全部测试工程。**
一轮撞过五次语义车，其中两次 git 全程沉默。

**8. 两窗把同一个递增号抬到同值 = 上服即崩。**
协议号、迁移号、版式号。git 只在那一行冲突，随手解就过，
盘上写出「半截 v7」，下一次开机崩。号面预分要写进任务书。

**9. 主检出别 `reset --hard`。**
主检出是共用的。跑之前先 `git status` 看别位的未提交件——实犯过，清掉过别人正在写的文档。

**10. 判过 ≠ 能并。别让主线红着过夜。**
退回要给隔离归因 + 逐条期望值 + 归属 + 「改测试还是改真源」。

**11. 别位报的支头多半已过期。**
一天撞过四次。按当前支头并，但先核祖先关系。

**12. 「台面已合并」≠ 已进主线；「文件进主线」≠ 规矩生效。**

---

## 判卷与派活的时候

**13. 总监判语是快照。落号前问一句「这条还成立吗」。**
判语常被拍板人在员工窗当面改掉。

**14. 引别位报的事实先自己核，包括上级裁定的前提。**
上级的裁定也建立在某个人报的数上，那个数也可能是抄来的。

**15. 甲档任务书别写方法。弱总监替强员工定方法是灾难。**
你会得到一个照做的平庸实现，而它本来能给你更好的。

**16. 跨位现象先定归属再派。**
两位各量一遍会连量三轮，然后互相说对方的数不对。

**17. 一个需求最多核对一次。第二轮直接找拍板人。**
第二轮来回几乎从不收敛，只会把两个人都拖住。

**18. 写「用户看得见」之前先 grep 消费端。服务端有 ≠ 屏上有。**
同类错连犯过三批。

---

## 跟人打交道的时候

**19. 讲数值给拍板人要用白话。**
说「两笔钱」他懂，说「双计费维度」他会说「没听懂」然后随便写一个。

**20. 画风别用「写实 / 卡通」二分，用参照作品名说话。**
抽象的风格词每个人脑子里的画面都不一样，作品名只有一种。

**21. 你在聊天里给的授权，改不了工具层。**
你说「以后这类脚本都可以直接跑」，窗口照样会被它自己的安全机制拦——
那个机制只看命令长什么样，不看你说过什么。所以：
授权要落到**工具认得的地方**（配置、白名单），或者干脆把脚本写成它不会拦的形状。
★推论：**聊天里说过、但没写进文件的，等于没说。** 下一扇窗读不到你的聊天记录。

## 附：闸的四条

- **闸只拦「活没做好」。** 卡住员工的工具账立刻修根。
- **闸不许挂在会移动的东西上。** 判据要能自证。
- **文本闸连注释也拦。** 解释「为什么不能写 X」时别把 X 抄进注释——一天撞过三次。
- ★**没被拦住过一次的闸，按不存在算。**
  加完闸必须**造一个它该拦住的场景真跑一遍**，看见它红了，再把这次验证写进回执。
  撞过的形状：一道「互相报备再动手」的闸，是拿关键词去扫整份收件箱的——
  而收件箱里一句**很久以前**的留言恰好含着那个词，于是等待被直接跳过。
  **闸看着在，其实从建好那天起就没拦住过任何东西**，也没人发现。
  同一条对测试成立：一条**从没红过**的用例，证明不了它在测什么。
