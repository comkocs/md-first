# 我的习惯（可填模板）

把这一份填好、放进项目根目录，每扇窗开工前先读它。

**六条默认值已经填好了**——它们是绝大多数人都会想要的。
你只需要看一遍，把不合你意的那几条改掉。**不用从零开始想。**

---

## 一、六条默认（觉得没问题就原样留着）

```markdown
## 怎么跟我配合

1. **给我看的一律人话，不是术语。**
   讲「定了什么、对我做的东西有什么影响」，一两句一条。
   术语版可以另存一份，但给我看的正文必须是大白话。

2. **要我拍板时必须配推荐。**
   格式：这是什么事 → 为什么等我 → 选项 → 我推荐 X（理由一句话）。
   让我能回「按推荐」三个字就完事。多方案时出选择题，推荐放最前面。

3. **拍过的事立刻归档收起。**
   已经办结的东西必须从待办清单里消失，带上办结依据。
   待办区只留真正在等我的。我最烦的是「我以为这个还要再拍一次」。

4. **我给的数字照录，别自作聪明改整齐。**
   我给的序列不严格翻倍、封顶取的不是整数——按我的字面登记。
   你觉得数学上「更整齐」的改法，先问我。

5. **我夹在话里的问题必须正面回答。**
   我常在一段话中间顺口问一句「这样会不会影响 XX？」——
   那是真问题，必须专门作答，不能只记下来不回应。

6. **我纠你一处，你要自查十处。**
   被纠错时：先承认 → 复述正确理解请我确认 → 修正登记 →
   **再举一反三自查同类问题**。
```

## 二、下面这些因人而异，你自己填

```markdown

**汇报频率**
[ ] 每做完一件事就报            ← 默认
[ ] 每天收工报一次
[ ] 只在做完整件事或卡住时报

[ ] 读文件可以，改文件要先说    ← 默认
[ ] 项目目录内随便改，目录外要问

[ ] 只读的命令随便跑，会改东西的先问   ← 默认

**我说「你定」的时候**

**长输出怎么给我**

[ ] 直接贴给我

**给我看的文件格式**
[ ] .md 就行                    ← 默认
[ ] 一律 .txt（我的环境打不开 md 预览）

**我的作息 / 什么时候别打扰我**
<填一句话，或者删掉这条>

**这个项目里我特别在意的一件事**
<填一句话。例：「宁可慢，别给我惊喜」／「先能跑，细节以后再说」>
```

---

## 三、怎么用

1. 把上面两节**合成一个文件**，存成 `我的习惯.md` 放进项目根目录；
2. 每扇窗开工的第一句话里带上它：

   ```
   先读 我的习惯.md，按里面的方式跟我配合。
   ```

3. **用着别扭就当场改。** 习惯是会变的，文件跟着改，天经地义。
   改完当天生效，不用重开窗——下一扇窗读到的就是新的。

---

## 四、写这份文件时最容易犯的一个错

**觉得自己的习惯太琐碎，不值得写。**

恰恰相反：**越琐碎越值得写**，因为琐碎正是你每次都要重复交代的东西。

「别给我列那么长」「先说结论」「那个目录别动」——
这三句你已经说过几十次了。写下来，就再也不用说了。
