# 上服清单

把工单台放到一台服务器上，让所有窗口（包括手机）都能连。**不上服也能用**：单机模式
（`--local`）什么都不配就能跑，这份清单只给要多机协作的人。

## 一次性：装

1. 域名解析：把你的域名 A 记录指向服务器公网 IP，等解析生效。
   不想用域名就跳过——证书 `CN` 填 IP 也能跑，客户端靠指纹认证书，不靠域名。
2. 云厂商安全组 / 防火墙：放行你在 `server.json` 里写的那个端口（默认 `8443/TCP`）。
   来源填 `0.0.0.0/0` 最省事，只填自己的出口 IP 更安全。
3. 抄一份 `deploy/server.example.json` 改成你自己的 `server.json`，然后：

```bash
sudo bash deploy/install.sh --config /path/to/server.json --source /path/to/ticket-desk
```

4. 安装脚本最后会打印首次设密链接，**只开放 30 分钟**：
   `https://<域名>:<端口>/setup`。用任意设备打开，自己设密码。
   超时了重跑一次 `install.sh --reopen-setup` 即可再开 30 分钟。

★ 任何人都不要在聊天、文件或命令行参数里写密码。

### 装的时候可能要加的三个参数

| 参数 | 什么时候要用 | 不用会怎样 |
|---|---|---|
| `--desk-config <你的 config.json>` | 你改过名册（多半都改过） | **配置会被上服删掉**，见下面那一节 |
| `--python-bin <解释器路径>` | 不能往系统 python 装包的机器 | 服务起不来（闸① 要求跑服务的 python 能 `import PIL`） |
| `--no-firewall` | 不允许改全机防火墙的环境 | 脚本会执行 `ufw allow <端口>/tcp`——那是一次**全机**写入 |

### ★名册配置不要放进包目录

`config.py` 找配置的顺序是「环境变量 `TICKET_CONFIG` → **本包同目录的 `config.json`**」，
而每次上服都会 `rm -rf app/ticket_desk`。**照第二条把配置放进包目录的人，第一次上服就丢名册**，
而且丢了不报错，是**静默回落到示例名册**——`config.py` 自己就写着
「配置文件写歪了却按示例名册跑起来，是这一类工具最坏的失败形态」，被上服删掉走的正是这条路。

用 `--desk-config` 装：文件会落在 `<安装目录>/config.json`（在 `app/` **之外**，上服的 `rm` 够不着），
并自动写一份 systemd drop-in 把 `TICKET_CONFIG` 指过去。
用 drop-in 而不是改单元本体，是因为单元本体是 `install.sh` 下次会整个覆盖的文件。

## 一次性：各个窗口接通道

5. 登录后打开「我的令牌」，生成一次性可见的 API token，存到本机一个令牌文件里。
6. 在 `remote.env` 里**只**填三样：远程地址、令牌文件路径、证书指纹。
   **不填 token 本文**——token 只躺在那个令牌文件里，`remote.env` 是要发给各个窗口的。

```ini
TICKET_REMOTE=https://desk.example.com:8443
TICKET_TOKEN_FILE=./service.token
TICKET_CA_SHA256=<openssl x509 -noout -fingerprint -sha256 算出来的那串，去掉冒号>
```

## 每次上服

```bash
# ① 打包（会把提交号写进包里并回验，拿不到提交号的包不要用）
bash deploy/pack.sh /tmp/desk.tar

# ② 先只跑闸，不动线上
sudo bash deploy/update.sh --source /path/to/unpacked --install-dir /var/lib/ticket-desk --check-only

# ③ 三闸都过了再真替换
sudo bash deploy/update.sh --source /path/to/unpacked --install-dir /var/lib/ticket-desk
```

三道前置闸任一不过 ⇒ 退出 2，**线上一个字节都没动**。
替换重启之后还有一道后置闸盯着端口真在听，不在听退出 3 并打日志。

上服还认两个可选参数：

- `--port <端口>`：不给的话从 systemd unit 的 `--port` **现读**，读不到才回落 `8443`。
  后置闸拿它当唯一判据，取错了就是一个**假红**——代码其实已经替换、服务也已经起来，
  人却看到「上服失败」，回头再跑一遍。
- `--target <部署目标>`：默认 `production`，透传给自动建的那张上服记录单。
  拿工单台**管别的系统**的时候这个必须给：不给的话，工单台给自己上服会把
  「production 部署头」那一格覆盖成工单台自己的提交号，而那一格记的是被管理的业务系统的头。

★ 不能往系统 python 装包、装的时候用了 `--python-bin` 的，每次上服也要带上
`PYTHON_BIN=<同一个解释器>`——闸① 探的是「这个解释器能不能 `import PIL`」。

## 备份

```bash
# cron: 0 3 * * * /var/lib/ticket-desk/app/deploy/backup.sh --install-dir /var/lib/ticket-desk
```

保留最近 14 天。备份走 `ticket.py dump` 而不是直接拷 `.sqlite`——服务开着 WAL，
直接拷到的可能是一份「看起来没坏、其实缺最后几笔」的库，而这种坏法只有恢复那天才会发现。
