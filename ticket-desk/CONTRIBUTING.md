# 改这个仓之前

1. 跑一遍 `python -m pytest tests -q`。483 条，应当全绿。**在脏树上报绿数不算数。**
2. 加闸就加用例，而且用例要能**真被拦过一次**才算数：
   只 grep 源码字符串的用例挡不住行为坏掉——这个仓栽过，全绿着把生产改坏两次。
3. 改注释前先读那条注释。多数注释写的是「不这么做会怎样」，
   删掉它等于把那次事故的记录一起删了。
4. 位名、模型名、值面项、上服目标一律走 `ticket_desk/config.py`，
   **不许在别处写字面量**。同一个事实写在两个地方必然漂，而且不报错。
5. 报「我改好了」之前，把东西放进某处之后**读回来比一次**。
   「打印了成功但其实没做成」是这个仓最常见的一类 bug。
